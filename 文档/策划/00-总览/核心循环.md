# 核心循环

> 状态：**已实现**  
> 技术对照：[../../技术/架构.md](../../技术/架构.md)

玩家只做三件事：建市政厅 → 雇牛马 →（可选）开规划 / 改计划。其余由系统在服务端跑。

## 玩家会话

```
建市政厅
  → 打开市政厅「牛马」页
  → 雇佣（或自动雇佣无业市民）
  → 牛马开始处理卡住请求（生成 → 配送）
  →（可选）打开「自主规划」
      固定式：按默认 12 步或玩家编辑的计划下工单
      启发式：按殖民地指标打分选下一座
  → 建造者施工；牛马继续补给卡住的建材/物资
```

## 系统双循环（互斥优先级）

同一名牛马 **先做补给，再做规划**：

1. **补给循环**（每服务端 tick，由 `BeastofBurdenWorkDriver` 驱动）  
   扫描卡住请求 → 排队 → 生成 → 走到目标 → 履约。  
   进行中时规划门控记为 `beast_busy`。

2. **规划循环**（市政厅模块慢 tick，约每 500 tick）  
   有已分配牛马、牛马空闲、建造者有空（或农田例外 / 冷启动例外）→ 选任务 → 选点 → 下工单。

两套循环共享：市政厅模块上的工作状态、工作日志、规划报告。

## 成功标准（策划验收）

- 无仓库时，市民/建筑的物品请求最终会被牛马补上，而不是永远停在请求板。
- 打开规划后，第一座建造者小屋能在没有现成建造者的情况下落下（冷启动）。
- 固定式默认计划能从「只有市政厅」走到大学，只要地形找得到点、建造者跟得上。
- 市政厅页能区分：待命 / 生成 / 配送 / 规划中，以及规划失败原因。

## 失败应可见

规划找不到点、重叠、无建造者、超出建造者范围、蓝图缺失等，必须写入 `PlanningReport.decision` 并显示在市政厅页，而不是只打日志。
