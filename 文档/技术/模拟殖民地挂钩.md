## 873 树里有什么（主对照）

规模约：API + 实现合计 **~2006** 个 `.java`；实现根包已是 **`com.minecolonies.core`**（不是 `coremod`）。农田在 **`colony.buildingextensions`**。

| 区 | 路径 | 说明 |
|----|------|------|
| API | `src/api/java/com/minecolonies/api/` | 对外接口、注册表、常量 |
| 实现 | `src/main/java/com/minecolonies/core/` | 殖民地逻辑、AI、建筑、网络、GUI |
| API 实现桥 | `src/main/java/com/minecolonies/apiimp/` | `*Initializer` |
| 蓝图 | `src/main/resources/blueprints/minecolonies/` | Structurize 风格包 |

### 顶层职责（按包）

**`com.minecolonies.api`**

| 子包 | 干什么 | 本模组是否常用 |
|------|--------|----------------|
| `colony` | 殖民地、市民、建筑、工单、权限、请求系统 | **是** |
| `colony.buildings` | `ModBuildings`、`IBuilding`、模块接口、`BuildingEntry` | **是** |
| `colony.jobs` / `jobs.registry` | `JobEntry`、`IJob` | **是** |
| `colony.requestsystem` | 请求、解析器、token、可配送物 | **是** |
| `colony.workorders` | `IWorkOrder`、`WorkOrderType` | **是** |
| `colony.buildingextensions` | 农田等建筑扩展（873+） | **是**（反射） |
| `entity.ai` / `entity.citizen` | AI 状态、技能、模型 | **是** |
| `blocks` / `util` / `compatibility.newstruct` | hut、工具、`BlueprintMapping` | **是** |

**`com.minecolonies.core`**

| 子包 | 干什么 | 本模组是否常用 |
|------|--------|----------------|
| `colony.buildings` | hut 实现、`modules`、`workerbuildings` | townhall / Farmer 反射 |
| `colony.jobs` | `Job*`、`AbstractJob` | **是** |
| `colony.requestsystem` / `workorders` | 请求与工单实现 | 对照 |
| `colony.buildingextensions` | `FarmField` 等 | **是**（反射） |
| `entity.ai.workers` | `AbstractAISkeleton`、胶带工具类 | **是** |
| `client.gui` | `SpecialAssignmentModuleWindow` | **是** |
| `MineColonies.java` | `@Mod` 入口 | 对照启动 |

### 873 vs 1214（快速对照）

两份都是 `core` + `buildingextensions`。1214 更新、类更多（约 2079 Java）；升版本前用 1214 树 diff 敏感 API（农田 create 签名、侧栏 mixin、胶带路径等）。

旧复制 `minecolonies-release-1.20` 仍是 `coremod` + `colony.fields`，**不要**再当 873 真相。

## 已知脆弱点

1. 反射农田 / 胶带：改名即崩；先在 873 树核对，再用 1214 树看是否变签名。
2. 模块侧栏：873 原生显示；1214 曾需要 mixin `shouldRenderDefaultSidebar`（本模组已删）。
3. `AbstractBlockHut.onBlockPlacedByBuildTool`、level 0 + requestUpgrade 是规划落 hut 的契约。
4. Job 模型必须 `SETTLER_ID`，`CITIZEN_ID` 会裁切。

升版本 checklist：对照本页 API 与反射表 → 跑 `runClient` 开市政厅页 → 冷启动第一座建造者 → 卡住请求生成配送 → 固定式走完第 1–5 步。
